## 0. 使用说明

### 0.1 本阶段的边界

V1.0.1 只交付**可被别人依赖的基座**，不交付 Agent 能力本身：

- 交付：基线 + CI、人物主数据、引用结构化、三份契约、数据快照、只读数据 API、前端壳层骨架、受控接口骨架、评测骨架、模型能力报告。
- 不交付：规划器、LLM 问答、ActionBus 真实执行、BM25/RAG、多轮记忆、完整 URL 状态化（这些属于 V1.0.3–V1.0.6，见 §1.4）。

## 2. 任务卡

### TC-01 基线冻结与 CI（§7-1）

- **目标**：把当前 V0.9.0 工作区固化成可回退的基线，并提供一条命令/一套 CI 作为后续所有卡的质量门禁。
- **依赖**：无。
- **输入**：HEAD `b1ef8f2`；当前工作区未提交改动（实测 10 个已跟踪文件被修改，另有审核报告/任务卡等新增文档）；现有校验命令 `tsc --noEmit`、`next build`、`node scripts/validate-data.mjs`。
- **输出**：
  - 提交 `chore(release): freeze v0.9.0 baseline` + 轻量 tag `v0.9.0`；
  - 本地一键校验脚本；
  - CI 工作流（有远端则启用，无远端时以本地脚本为准）。
- **文件改动**：

| 文件 | 动作 | 说明 |
|---|---|---|
| `.github/workflows/ci.yml` | 新增 | frontend job：Node 22 + pnpm install + tsc + build + validate-data；可选 backend job：Python 3.11 编译检查 |
| `scripts/verify.ps1` | 新增 | 串行执行 3 项校验，任一项失败即非 0 退出 |
| `README.md` | 修改 | 增补"验证"一节，写明 `scripts/verify.ps1` 与 CI 状态 |

- **关键约束**：
  - 先提交再打 tag，tag 指向基线提交；tag 名必须 `v0.9.0`（与 package 版本一致）。
  - 不在本卡修正数据或改业务逻辑；工作区里只有 V0.9.0 的既有改动。
  - CI 如果因仓库未托管在 GitHub 无法运行，必须在验收记录里注明"本地脚本为权威门禁"。
- **验收标准**：
  1. `git status --porcelain` 为空；`git describe --tags --exact-match` 返回 `v0.9.0`。
  2. `pwsh scripts/verify.ps1` 退出码 0，输出三项 PASS（tsc / build / validate-data）。
  3. `node scripts/validate-data.mjs` 末尾为 `ALL CHECKS PASSED`。
  4. CI 文件 YAML 可解析；若启用远端，push 后 1 次构建通过。
  5. 单项校验耗时合计 < 5 分钟（本地）。
- **规模**：S（0.5–1 人日）。
- **可并行**：否（所有卡的前置）。

### TC-02 人物主数据与消歧（§7-3）

- **目标**：为 1059 个姓名建立稳定的 `person_id` 主数据、消歧副标题、全局别名与同名报告，解决"人物 ID = 姓名"的 P0 问题；本卡不迁移图谱与关系库的渲染口径。
- **依赖**：TC-01。
- **输入**：
  - `frontend/data/timeline-participants.ts` + `frontend/data/weijin-events.ts`：705 条事件（671 时间轴 + 34 图谱补足）的参与者姓名（实测 1059 个去重姓名）；
  - `frontend/data/person-graph.ts`：18 期 + 7 组的图成员（用于 `eraIds/scopeIds`）；
  - `frontend/data/person-graph.ts` 的 `PERSON_NAME_ALIASES`（66 条）与 `KEY_FIGURES`；
  - 已确认的同名异人：`梁太后`（东汉 146 / 西夏 1081–1082）、`刘崇`（西汉 6 / 五代 954）；`朱熹` 的"提及"问题记录但不拆分。
- **输出**：
  - 生成式人物主数据 + 人工覆盖层；
  - 稳定 ID 与锁文件；
  - 同名/歧义报告（供人工裁决并留档）；
  - 别名全局索引（原图谱内搜索别名升级为全局）。
- **文件改动**：

| 文件 | 动作 | 说明 |
|---|---|---|
| `frontend/data/persons.generated.ts` | 新增（生成） | 由脚本生成，含 1059+ 条人物主数据 |
| `frontend/data/person-overrides.ts` | 新增（人工） | 拆分/合并/ID 固定/消歧补充；唯一允许手改的文件 |
| `frontend/data/persons.ts` | 新增 | 合并 generated + overrides 的对外读取入口 |
| `frontend/data/person-aliases.ts` | 新增（生成+人工） | 66 条现有别名迁入，按 `person_id` 归一 |
| `frontend/data/locks/person-ids.lock.json` | 新增（生成） | `person_id → displayName/firstYear/hash`，防止 ID 漂移 |
| `scripts/build-persons.mjs` | 新增 | 生成/校验脚本，支持 `--check` |
| `docs/person-same-name-report.md` | 新增 | 同名组、年份跨度、裁决结论 |
| `scripts/validate-data.mjs` | 修改 | 增加人物主数据层校验 |
| `frontend/package.json` | 修改 | 新增 devDependency `pinyin-pro`（用于生成可读 slug；若评审拒绝新增依赖，退化为 8 位哈希 ID） |

- **关键约束**：
  - ID 规则：`p-<罗马化姓名>-<4位hash>`，hash 由 `displayName + firstEventYear + primaryDynasty` 生成；同名拆分用 `person-overrides.ts` 固定 ID。**ID 一旦发布不可变**，改名/合并走 `mergedInto`（V1.1 实现，本卡先留字段）。
  - 字段至少包含：`id / displayName / romanized / disambiguator{period,role} / aliases[] / primaryDynasty / dynasties[] / eraIds[] / scopeIds[] / eventIds[] / firstYear / lastYear / status`。
  - `primaryDynasty` 取"最后一条关联事件的 dynasty"（与现有 `PersonGraphNode.dynasty` 口径一致），全部朝代放 `dynasties[]`。
  - 单图内姓名唯一是既有事实；本卡**不**把图节点 ID 从姓名改成 `person_id`（V1.1 再做）。
  - 同名组必须有明确裁决：拆分为两条，或写清"同一人"的理由；不允许静默合并。
- **验收标准**：
  1. `node scripts/build-persons.mjs` 连续执行两次输出一致；`--check` 退出码 0。
  2. `persons` 总数 = 1061（1059 + 梁太后/刘崇各拆分 1 人）；若算法发现新的同名组，数量可变但必须在报告里逐组裁决并记录。
  3. 每个事件参与者（`participants` 中的每个姓名）至少映射到 1 个 `person_id`；每个 `person` 至少关联 1 条事件。
  4. `person_id` 全局唯一，符合约定正则；无 `year=0`；`firstYear ≤ lastYear`。
  5. `梁太后` 返回 2 个候选（东汉·梁冀妹 / 西夏·毅宗后）；`刘崇` 返回 2 个候选；66 条别名全部能解析到 1 个 `person_id`，歧义别名（若拆分后出现）必须显式处理。
  6. `docs/person-same-name-report.md` 列出全部同名组、年份跨度、裁决结论与责任人。
  7. `pnpm exec tsc --noEmit` 0 error；扩展后的 `node scripts/validate-data.mjs` 通过；`person-ids.lock.json` 重跑无 diff。
- **规模**：L（2–3 人日）。
- **可并行**：否（关键路径）；可与 TC-10 并行。

### TC-03 引用结构化 sourceRefs（§7-6）

- **目标**：把事件正文末尾的「（据《…》）」转成结构化引用；同时确定"关系定性只能引共同事件书目"的边界。
- **依赖**：TC-01；技术上可与 TC-02 并行，但按本文件波次在 TC-02 之后执行（单人开发建议顺序执行）。
- **输入**（已实测）：
  - 705 条事件中 704 条含「据《…》」，仅 `special-star-1893` 没有；
  - 585 条 1 本书、119 条 2 本书（同一括注内并列），合计 **823 条引用**；
  - 书目标签 185 种（如 `宋史`、`史记·秦始皇本纪`、`旧唐书`）；
  - 639 条关系记录中 283 条有人工描述、711 条 `eventSummaries`；关系描述**没有**书目，按已确认边界处理。
- **输出**：
  - 事件 → 结构化引用索引；
  - 抽取/校验脚本与人工复核清单；
  - 关系引用的派生规则（在快照阶段落地）。
- **文件改动**：

| 文件 | 动作 | 说明 |
|---|---|---|
| `frontend/data/event-sources.ts` | 新增（生成） | `EVENT_SOURCES: eventId → SourceRef[]` |
| `scripts/extract-sources.mjs` | 新增 | 从 description 末尾解析「据《…》」，支持并列多本，支持 `--check` |
| `docs/source-review.md` | 新增 | 185 个标签的归一化说明、例外清单（彩蛋）、人工复核记录 |
| `scripts/validate-data.mjs` | 修改 | 校验事件与引用索引双向一致、引用数、书目非空 |

- **关键约束**：
  - `SourceRef` 字段：`label`（原样，如"史记·秦始皇本纪"）、`book`（按首个"·"切分）、`chapter?`、`raw`（原文括注片段）。
  - 关系类引用不新增书目：引用构造时取该关系 `eventSummaries` 指向的共同事件的书目；关系定性标注「史脉关系库（人工校订）」。此规则写入 `docs/source-review.md`，由 TC-05 在快照里生成 `basis_event_ids`。
  - 彩蛋事件必须有显式 `sourceRefs: []` + `sourceStatus: "easter_egg"`，不得参与事实回答。
  - 不在本卡修改 `description` 原文（避免破坏展示与历史 diff）。
- **验收标准**：
  1. `node scripts/extract-sources.mjs` 输出 705 个键；其中 704 条非空、1 条彩蛋为空。
  2. 引用条目总数 = 823；每本 `book` 非空；`label` 与原文括注完全一致（可回查子串）。
  3. `node scripts/validate-data.mjs` 通过（新增：缺引用、悬空 eventId、引用数不符均失败）。
  4. `docs/source-review.md` 覆盖全部 185 个标签；人工抽查 ≥10% 的 2 书并列条目，结论记录在案。
  5. `pnpm exec tsc --noEmit` 0 error。
- **规模**：M（1–1.5 人日）。
- **可并行**：是（与 TC-04）。

  5. 误删任一用例的引用 ID 时，contract 模式必须失败（负向测试）。
- **规模**：M（1–1.5 人日）。
- **可并行**：是（与 TC-06/07）。

### TC-10 模型能力 spike（§7-10）

- **目标**：在写任何规划器代码前，验证 XiaoHong-v1 经 OneAPI 的真实能力与限制，形成"支持/不支持/降级"的书面结论。
- **依赖**：无（需要你提供网关地址、模型名、临时 key；key 不入库）。
- **输入**：OneAPI 的 base URL、模型名、凭据；报告 §5.8 的探针清单。
- **输出**：探针脚本 + 能力报告 + 降级路线建议。
- **文件改动**：

| 文件 | 动作 | 说明 |
|---|---|---|
| `backend/scripts/spike_llm.py` | 新增 | 只读探针，读环境变量；不被应用导入 |
| `docs/spikes/xiaohong-v1-capability.md` | 新增 | 每项能力 PASS/FAIL + 证据 + 结论 |
| `docs/spikes/spike-README.md` | 新增 | 如何复现（环境变量、命令、脱敏说明） |

- **探针清单**：
  1. OpenAI 兼容性：`/v1/models`、`/v1/chat/completions`；
  2. JSON 输出：`response_format=json_object` 是否支持、非法 JSON 比例；
  3. tool/function calling：是否支持、并行调用、参数稳定性；
  4. 流式：SSE 是否可用、首字延迟；
  5. 上下文：模型上限、8 条检索片段的稳定性；
  6. 中文质量：150–400 字历史回答的可读性与事实一致性（用固定 10 题）；
  7. 确定性与延迟：同 prompt 3 次差异、P50/P95；
  8. 错误码与限流：429/5xx 行为、重试建议；
  9. 成本：按 token 估算单次问答成本；
  10. 数据合规：请求是否出境/可关闭日志（向提供方确认）。
- **关键约束**：
  - 凭据只经环境变量传入，不写入仓库、不写日志；报告里只记录脱敏后的 base URL。
  - 结论必须给出**无 tool calling 时的降级方案**（单次 JSON 意图抽取 + 规则执行）。
  - 不根据 spike 结果写业务代码；只产出报告与建议参数（temperature、max_tokens、timeout、重试）。
- **验收标准**：
  1. 报告包含 10 项探针的 PASS/FAIL 与证据（请求/响应摘要、耗时）。
  2. 明确结论：V1.0.3 采用"tool calling"还是"JSON 意图抽取 + 规则"，并说明理由。
  3. 给出推荐参数与超时/重试/最大轮数建议。
  4. 仓库中无任何真实 key（`git grep` 检查通过）。
  5. 成本估算（单次问答 / 1000 次）与延迟 P50/P95 记录在案。
- **规模**：S（0.5–1 人日，视凭据可用性）。
- **可并行**：是（建议第 0 波启动）。

## 4. 风险与回退

| 风险 | 影响 | 回退/缓解 |
|---|---|---|
| 同名裁决不准（如把不同人合并） | 工具答错人 | 全部裁决集中在 `person-overrides.ts`；ID 锁文件 + 报告可回滚；V1.0.1 不改图渲染，影响面可控 |
| 契约冻结过早/字段缺失 | V1.0.3/4 返工 | 只允许新增可选字段；V1.0 内不升大版本；契约评审后再开工 |
| TS 转译加载器在 CI 环境差异 | 快照/校验失败 | 共享 `scripts/lib/load-ts-data.mjs`；CI 与本地同一 Node 大版本；失败即阻断 |
| 快照体积/加载变慢 | 后端启动慢 | 预算 <5MB；超限则拆分为 events/persons/graphs 三文件并懒加载（本卡不做） |
| 后端拆分破坏启动脚本 | 本地一键启动失败 | 保留 `backend/main.py` 的 `main:app` 入口；TC-06 验收含 `launch.ps1` 回归 |
| 前端 Provider 影响 SSR | 构建/水合失败 | Provider 为客户端组件、只在 `layout` 包一层；`useSearchParams` 放 Suspense |
| 模型 spike 缺凭据 | 阻塞 TC-10 | TC-10 不进关键路径；缺凭据时先交付探针脚本 + 空报告，标记 blocked，不阻塞其余卡 |
| 范围膨胀（顺手做 UI/LLM） | V1.0.1 延期 | §1.3 范围外清单作为评审否决项 |
