### 2.2 220 年边界（唯一涉及既有数据的改动）

现有事件 `handong-han-fall`（曹丕篡汉，220，东汉）正好是分界点。

- **方案 A（推荐）**：仅改其 `dynasty: "东汉" → "三国"`，`id`、`year`、`title`、`description`、`participants` 全部不动。
  - 收益：三国 Tab 有开国事件；秦汉图谱期自然结束于 208 赤壁。
  - 代价：东汉 Tab 最后一条变为 208 赤壁。
- **方案 B**：不动它，三国 Tab 从 221 刘备称帝开始。
  - 收益：零既有数据改动；代价：三国 Tab 缺「曹丕代汉」。

### 2.3 三国图谱的事件来源

三国期图不做「只读三国 dynasty」，否则曹操、刘备、孙权、关羽都没有边。
做法：`person-graph.ts` 里新增一个**事件 id 白名单**，`buildPersonGraph` 一行不改：

```ts
const SAN_GUO_EVENT_IDS = [
  "handong-dongzhuo", "handong-liandong", "handong-dongzhuo-death",   // 189/190/192 汉末
  "handong-caocao-emperor", "handong-guandu", "handong-chibi",          // 196/200/208
  "handong-han-fall", "handong-fanchang",                              // 220（迁移后）+ 219 新增
  ...三国 11 条,
];
// 实现落点：ERA_GRAPHS.sanguo
const SAN_GUO_GRAPH = buildPersonGraph(
  TIMELINE_EVENTS.filter((event) => SAN_GUO_EVENT_IDS.includes(event.id)),
  ["东汉", "三国"],
);
```

节点 `dynasty` 由「最后出现事件」推导（现有逻辑），曹操等自然落在「三国」。

### 4.2 阵营快捷按钮（仅三国期渲染）

| 按钮文案 | 触发 | 实现 |
|---|---|---|
| `魏 · 曹操` | `applyCenterPerson("曹操")` | 复用现有换中心入口 |

- 高亮：`centerPersonId` 等于对应君主时按钮呈 active。
- 数据：`person-graph.ts` 导出 `SAN_GUO_FACTION_SHORTCUTS`，页面只负责渲染。

## 12. 两人关系数据结构与校验记录

### 12.1 数据结构

```ts
// frontend/data/person-relations.ts
interface PersonRelationRecord {
  a: string;                                  // 人物甲
  b: string;                                  // 人物乙
  label: string;                              // 关系定性：对手 / 君臣 / 盟友 / 政敌 / 降将 / 义父子→反目 …
  description?: string;                       // 关系来龙去脉（核心对才写）
  eventSummaries: Record<string, string>;     // 键 = 共同事件 id，值 = 这对人物视角的事件简述
}
```

- 与事件库解耦：键是人物对，图谱构建时用统一排序口径 `pairKey(a, b)` 挂到边上。
- `PersonGraphEdge.relation` 为可选字段；未收录的人物对不显示关系徽章，事件简述回退 `GraphEventReference.summary`（即事件正文摘要）。
- 跨分期共用：秦汉期若有同名人物对（如 曹操 × 刘备），同样会显示关系徽章。
