## 1. 目标与边界

V1.0.5 在 V1.0.3「图谱工具 + 证据校验」的基础上补一层**长文史料检索（RAG）**，形成混合架构：

| 层 | 数据 | 回答中的位置 | 权威性 |
|---|---|---|---|
| 图谱层（V1.0.2/1.0.3） | 705 事件 / 1,058 人物 / 639 关系的结构化快照 | ① 基础事实 | **年份 / 人物以图谱为准** |
| 史料层（V1.0.5） | 51 篇语料的 186 条 chunk（白话 + 古文原典） | ② 史料记载细节（带 citations） | 细节补充；与图谱冲突时标注「史料记载有异」 |

关键约束（延续 V1.0.3 的安全模型）：

- **不允许模型写用户可见正文**：正文仍由服务端用工具真实数据重组；RAG 只决定「选中哪些史料」；
- **Token 有界**：单次 RAG 检索最多 3 条、每条正文最多 300 字；
- **不编造**：图谱与 RAG 都没有结果时强制 `insufficient`；证据不可核验时强制降级。

## 2. 架构

```
                     ┌──────────────────────────────────────────┐
docs/*.md（51 篇） → │ scripts/ingest_rag.py                    │
                     │   rag.corpus：## 事件名 锚点 → ≤500 字 chunk │
                     │   rag.embedding：ModelScope→fastembed→hash │
                     │   chromadb 持久化 backend/data/chroma_db/  │
                     └──────────────────────────────────────────┘
                                        │ manifest.json
                                        ▼
POST /api/agent/ask → AgentOrchestrator ── ToolRegistry ──┬─ 8 个图谱工具（V1.0.2）
                                        │                 └─ search_historical_text（V1.0.5）
                                        ▼
                              EvidenceValidator
                       （grounded 正文 = ① 图谱 / ② RAG 分节）
```

### 2.1 入库管道（`backend/rag/corpus.py` + `backend/scripts/ingest_rag.py`）

1. 以 `## 事件名` 为锚点切分两份 Markdown；
2. 每篇解析：
   - `### 白话文详述` → 白话 chunk；
   - `### 古文原典摘录` → 按 `**出处：《史记·商君列传》**` + `> 引文` 拆成若干古文 chunk；
3. chunk 规则：段落优先、句子兜底、超长硬切；**硬上限 500 字**，累计 ≥320 字封口（目标 300–500 字），
   实测 min 23 / max 493 / avg 206（古文短引文会低于 300 字，属预期）；
4. 元数据（同时写入 chromadb metadata 与工具返回）：

| 字段 | 示例 | 说明 |
|---|---|---|
| `chunk_id` | `rag-04-00` | 稳定 id，**同时用作 citation id** |
| `event_name` / `title` | 商鞅变法 | 标题 / 去标记后的干净标题 |
| `record_type` / `type` | 正史 / 传说 | 标题含 `【传说】` → 传说 |
| `section` | 白话文详述 / 古文原典摘录 | chunk 来源小节 |
| `source` / `source_label` / `book` / `chapter` | 史记 / 《史记·商君列传》 / 史记 / 商君列传 | 古文出处；白话为「史脉综述」 |
| `year_min` / `year_max` | -356 / -350 | 语料中抽到的纪年区间（用于交叉校验） |
| `event_id` | `zhanguo-05` | 入库时按标题对齐图谱事件（对齐不到为 null） |

5. 写库：`chromadb.PersistentClient(backend/data/chroma_db)`，collection `histolink_rag_v1`，`hnsw:space=cosine`；
6. 写 `manifest.json`：`schema / collection / embedding_provider / embedding_model / embedding_dim /
   document_count / chunk_count / corpus_sha256 / built_at / chroma_version`。

### 2.2 Embedding 选型（`backend/rag/embedding.py`）

产品要求「本地跑 sentence-transformers 困难时用 ModelScope API（bge-small-zh-v1.5）」。
实测结论：**当前 ModelScope 推理 API 未开放 embedding 模型**（`/v1/models` 仅对话/多模态模型，
`/v1/embeddings` 对 `BAAI/bge-small-zh-v1.5` 返回 `Invalid model id`）。因此实现 provider 链：

| 顺序 | provider | 说明 |
|---|---|---|
| 1 | `modelscope` | OpenAI 兼容 `/embeddings`；key 可用时零本地算力。当前账号探测失败自动跳过 |
| 2 | `local` | `fastembed` ONNX **BAAI/bge-small-zh-v1.5**（512 维，CPU，约 95MB，无需 torch）；**当前实际使用** |
| 3 | `hash` | 纯 Python 字符 n-gram 有符号哈希（512 维），完全离线兜底，只在无法下载模型时使用 |

- 入库时 `auto` 依次探测；实际 provider 写入 manifest；
- 运行期 **严格按 manifest 重建同一个 provider**（维度 / provider 不一致直接报错），避免向量空间错配；
- 可用 `RAG_EMBEDDING_PROVIDER=auto|modelscope|local|hash` 覆盖；`HF_ENDPOINT` 默认 `https://hf-mirror.com`。

### 2.3 向量库与检索（`backend/rag/store.py`）

- `get_rag_store()`：进程内单例，**首次调用才加载** chromadb + 模型（约 10s，之后复用；不拖慢服务启动）；
- `search(query, top_k=3)`：返回 `RetrievedChunk`（正文 + 全部元数据 + cosine 相似度）；
- 未入库 / 模型不可用 → `RagUnavailableError`；工具层转成 `INSUFFICIENT_EVIDENCE` 失败信封。

## 3. 工具层：`search_historical_text(query, top_k=3)`

- 位置：`backend/agent/tools/rag.py`；契约：`contracts/tools.py` 第 9 个工具；参数模型：`agent/tool_registry.py`；
- 入参：`query`（1–200 字，混合路由下 = 用户问题 + 图谱实体/年份）、`top_k`（1–3，**超过 3 直接 `INVALID_REQUEST`**）；
- 返回统一信封 +：
  - `items[]` / `data.chunks[]`：`chunk_id / event_name / title / text / type / record_type / section /
    source / source_label / book / chapter / event_id / score`；
  - `citations[]`：`kind="rag"`、`id=chunk_id`、`event_id`（对齐到图谱时可直接跳时间轴）、`quote`（≤300 字）、
    `record_type`（正史/传说）、`source_ref`、`attribution`；
- **Token 控制**：单次 ≤3 条 × 每条 ≤300 字（截断加省略号，总字符 ≤ 300 含省略号）；
- 空结果语义：`ok=true` + `data.total=0`（「查无」≠ 报错）。

## 4. Agent 混合路由

### 4.1 System Prompt（`backend/agent/prompts.py`）

新增/调整：

1. **先图谱后 RAG（硬性顺序）**：事件/人物问题必须先调用至少一次图谱工具；图谱 `total=0` 才可直接 RAG / insufficient；
   明确的上古传说（黄帝战蚩尤）例外；
2. **禁止零工具 final**：至少查一次再决定 grounded / insufficient；
3. RAG 组合查询：`query = 用户问题 + 图谱实体名 + 年份`，`top_k` ≤3；
4. 证据规则扩展：`entity_type="rag"`，`entity_id` 必须是 `chunks[].chunk_id`（= citation id）；
5. 交叉校验：以图谱为准，RAG 冲突不改成 insufficient（服务端会自动标注）；
6. 传说：`record_type=传说` 的史料必须作为 evidence，服务端在句首加 `[传说]`；
7. 双空兜底：两套工具都无结果 → `insufficient`（`NO_MATCHING_ENTITY` / `INSUFFICIENT_DATA`），不得编造；
8. Orchestrator 在 System Prompt 注入 **RAG 向量库状态**（manifest 篇数 / chunk 数 / provider），
   未入库时明确告知模型不要调用；
9. **输出长度硬约束**：`claims` 最多 3 条、`evidence` 最多 4 条。实测 Qwen 在长史料上下文下
   曾按句拆出 100+ 条 claims 导致 JSON 超 `max_tokens` 被截断（协议错误 → insufficient），
   加入该约束 + 修复轮提示后恢复正常；
10. **轮次硬上限 4 → 6**：V1.0.5 混合路由（图谱 1–2 轮 + RAG 1 轮 + final）外加 JSON 修复轮，
    4 轮经常被挤爆；6 轮仍是有界闭环（典型问题 2–4 轮完成）；
11. **相关性优先 + 无直接记载必须 insufficient**：Prompt 明确「出现同一个人物/时代 ≠ 相关」，
    问「某人是否做过某事 / 某物是否存在」而两套工具都无直接记载时，禁止用旁证强行 grounded
    （实测修复「秦始皇吃过西红柿吗」曾被「秦始皇统一六国 + 张骞通西域」凑成 grounded 的问题）；
12. **延迟治理**：后端启动时用守护线程预热 RAG 向量库（chromadb + ONNX 约 10s，不阻塞健康检查）；
    Next dev 同源代理 `experimental.proxyTimeout` 由默认 30s 放宽到 120s（首个混合回答可能 >30s，
    否则代理会 ECONNRESET，前端看到 500）。

### 4.2 证据模型（`backend/agent/schemas.py` / `validator.py`）

- `EvidenceKind` 新增 `rag`；
- `ObservedEvidence` 吸收 RAG 工具信封：citation → `("rag", chunk_id)` 实体（citation 形态），
  `items[]` 合并为 `structured` 详情（含 `year_min/year_max/record_type/section`）；
- `_citation_supports`：rag 证据 ↔ rag citation 一一对应（`citation.id == entity.entity_id`）。

### 4.3 结构化正文（服务端生成，模型无法改写）

有 RAG 证据时按固定分节：

```
① 基础事实（来自图谱）
<事件/人物/关系正文；无图谱事实时写“本轮未获取到图谱基础事实…”>

② 史料记载细节（来自 RAG）
<如冲突：史料记载有异：图谱系「X」于Y年，RAG 史料记载涉及…。年份存在出入时以图谱为准…>
[传说] <chunk 正文>（《史记·五帝本纪》·古文原典摘录）
<chunk 正文>（《史记·商君列传》·古文原典摘录）
```

- 标题、冲突文案、`[传说]` 标签均为服务端常量写死；
- 无 RAG 证据时保持 V1.0.4 的单段正文（向后兼容）；
- 分节顺序固定：图谱证据在前、RAG 证据在后（不信任模型给的 evidence 顺序）。
- `certainty`：全部「详情级」证据 + 结构化书目 → high；RAG/摘要级 → medium；insufficient → low。

### 4.4 交叉校验与冲突处理

- 图谱事件年份 vs 语料纪年区间（`year_min`—`year_max`，来自白话文里抽到的年份）：
  - 图谱年份落在区间内 → 不冲突（多年度叙事，如「贞观之治 627—649」）；
  - 图谱年份在区间外 → 标注「史料记载有异……以图谱为准」（例：商鞅变法图谱 -359、语料首见 -356/-350）；
- 冲突检测是**确定性、可服务端复核**的规则；人物层面的「以图谱为准」由 Prompt 约束 + ① 分节保证；
- 已知限制：中文数字纪年（「二十二年」）不抽取；语料纪年区间是「文档级」而非逐句级，
  仅用于年份冲突提示，不参与事实生成。

## 7. 已知限制与后续

1. **ModelScope 未开放 embedding**：当前走本地 fastembed；若后续 API 开放，`RAG_EMBEDDING_PROVIDER=modelscope`
   并重建向量库即可（manifest 会记录新 provider）。
2. **语料规模小（186 chunk）**：检索质量好但覆盖有限；扩语料后直接重跑 `ingest_rag.py`。
3. **年份冲突是启发式**：基于文档级纪年区间；人物冲突依赖 Prompt 约束，未做 NER 级比对。
4. **首查询延迟**：进程内首次 RAG 调用需加载 chromadb + ONNX 模型（约 10s）；后端启动时已用守护线程
   预热，正常情况下用户首个问题不再承担冷启动（`RAG` 未入库时预热自动跳过）。
5. **向量库不入库**：`backend/data/chroma_db/` 已 gitignore；新环境必须重跑入库脚本（README / `backend/data/README.md` 已说明）。
6. **RAG 结果仅作史料细节**：`insufficient` 判定仍要求图谱或 RAG 至少一方有可核验证据；模型无法凭 RAG 正文编造图谱事实。

## 8. 高可用补丁：LLM 自动降级（2026-11-24）

> 背景：ModelScope 免费额度在高峰期会返回 429 限流，偶发 502/504 网关错误；
> 单靠重试同一模型无法恢复，因此补一层「主模型失败 → 备用轻量模型」的自动降级。

### 8.1 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `MODELSCOPE_MODEL` | `Qwen/Qwen3.5-35B-A3B` | 主模型（质量优先） |
| `MODELSCOPE_FALLBACK_MODEL` | `Qwen/Qwen3.5-8B-Instruct` | 备用轻量模型（额度更宽松）；与主模型同名时自动禁用降级 |

> 本项目没有独立的 `config.py`：LLM 配置统一由 `backend/llm_client.py` 的
> `load_llm_settings()`（`LLMSettings`）从环境变量 / `backend/.env` 读取，本补丁在该处新增
> `fallback_model` 字段，未引入新的配置层。

### 8.2 降级规则（`LLMClient.chat()`）

| 主模型结果 | 行为 |
|---|---|
| 200 | 直接返回，`model_used = 主模型` |
| HTTP **429**（限流）、**502 / 504**（网关错误）、`httpx.TimeoutException`（超时） | 记 **warning** 日志 → 用备用模型**重试一次**；成功则 `model_used = 备用模型`，并在 `trace.model_used` 回传 |
| 其它错误（400 / 401 / 302 / 500 / 503 等） | 不降级，按原语义抛出（换模型也不会修好） |
| 备用模型重试仍失败 | 抛出 `LLMUpstreamError` / `LLMTimeoutError`（消息带「已降级重试，仍失败」上下文），API 层映射 502 / 504 |

- 只重试**一次**，不做指数退避，避免前端等待时间翻倍；
- 降级信息只进日志与 `trace`，不影响 `answer` 正文、证据校验与安全模型。

### 8.3 契约与前端

- `Trace.model_used`（可选，V1.0 只增不破坏）：最终完成回答的模型名；`AgentResult.model_used`
  由 Orchestrator 取「最后一轮 chat 的实际模型」贯通到 API。
- 前端 `answerViewFromEnvelope` 归一化 `modelUsed`；非 35B 时在回答气泡下方追加一行灰字
  「当前网络繁忙，史令已切换至轻量模型回答」（抽屉与 `/ask` 均支持，属可选提示）。
