## 1. 背景与用户反馈

V1.0.5.2 UI 呼吸感补丁把 `/ask` 做成了「单一文档滚动」模型（整页高度随内容撑开、输入区 sticky 吸附）。在实际使用中出现三组体验问题：

1. **整页滚动失控**：浏览器窗口出现滚动条，滚动鼠标时左（历史对话）/ 中（聊天）/ 右（史引时间轴）三块内容一起移动，长回答下体验极差。
2. **侧边栏点击重排（严重 Bug）**：点击左侧任意一条历史记录查看时，该条目会被自动移到列表最顶部，用户失去位置感。
3. **侧边栏功能缺失**：历史记录没有置顶 / 重命名 / 删除入口；「新建对话」只清空聊天区但不落列表；删除 / 置顶没有本地状态逻辑。

本补丁逐项修复以上问题，全部为前端布局与本地状态层改动：**不改后端 API 契约、不改 Agent 能力、不新增依赖**。

---

## 2. 根因分析

### 2.1 整页滚动：单一文档滚动模型

- `.appFrame` / `.page` / `.shell` / `.workspaceLayout` 均使用 `min-height: 100dvh` / `min-height: clamp(...)` 且没有 `height`，内容多长页面就多高；
- `.chatCard`、`.transcript` 是 `overflow: visible`，长回答直接撑开页面；
- 输入区 `position: sticky; bottom: 0` 属于「整页滚动 + 底部吸附」方案；
- 侧边栏 `position: sticky; height: 100dvh` 仍跟随文档滚动。

结果：文档是唯一滚动容器，左右两栏只能跟着一起滚。

### 2.2 点击重排：把「查看」误当成「最新活跃」

点击历史记录的数据流如下（修复前）：

```
点击条目 → loadConversation(id)
  → ① 先 repository.save(当前会话)   // save 内部无条件 updatedAt = now()
  → ② setTranscript(目标会话)
  → ③ transcript 同步 effect 再次 repository.save(target)  // 又把目标会话 updatedAt = now()
  → ④ refreshConversations() → list() 按 (pinned, updatedAt desc) 重新排序
```

即「点击查看」触发了两次「刷新最后消息时间」，目标会话因此被排到最顶部（旧代码里还会从「过去 30 天」组跳到「今天」组）。这是排序语义错误，不是 UI 动画问题。

### 2.3 新建对话不落列表

旧实现只有出现首条用户消息时才 `repository.create()`，点击「新建对话」只清空 transcript；用户看不到「新会话出现在最上方」的反馈。

## 3. 修复方案

### 3.1 全局布局锁死：100vh App Shell + 三栏独立滚动

| 层 | 修复后规则 |
|---|---|
| `html` / `body` | `/ask` 挂载时加 `askAppShell` 类：`height: 100%; overflow: hidden; overscroll-behavior: none;`；离开页面移除，不影响其他页面 |
| `.appFrame` | `height: 100dvh; overflow: hidden; display: flex` |
| `.page` / `.shell` | `height: 100%; min-height: 0; overflow: hidden; display: flex; flex-direction: column` |
| `.workspaceLayout` | `flex: 1 1 auto; min-height: 0; overflow: hidden`（不再有 `min-height: clamp(...)`） |
| `.chatCard` | `height: 100%; min-height: 0; overflow: hidden` |
| `.conversationBody` | `flex: 1 1 auto; min-height: 0; overflow: hidden` |
| `.transcript`（中间聊天区） | **唯一中间滚动容器**：`flex: 1 1 auto; min-height: 0; overflow-y: auto; overscroll-behavior: contain` |
| `.guideRail`（右侧史引联动栏） | `min-height: 0; overflow-y: auto; overscroll-behavior: contain` |
| `.composerDock` | 取消 `sticky`，作为聊天卡片最后一块固定在卡片底部 |
| `.copilotPanel`（右侧史引分屏） | `height: 100%; min-height: 0; overflow: hidden`，内部 iframe 独立滚动 |

验收口径：任意窗口尺寸下 `document.documentElement.scrollHeight <= innerHeight + 1`；中间滚轮只改 `.transcript.scrollTop`，左侧滚轮只改侧边栏 `.scrollArea.scrollTop`，两者互不影响且整页 `scrollY === 0`。

### 3.2 中间聊天区滚动行为

- **首屏 / 刷新**：挂载并恢复会话后，瞬时滚动到聊天列表底部（显示最新消息）；
- **发送新问题 / AI 返回新回答 / 检索中**：`requestAnimationFrame` 后平滑滚动到底部；
- **切换左侧历史对话**：会话内容换入后强制瞬时滚到底部，不复用上一会话的滚动位置；
- **补滚**：`ResizeObserver` 监听聊天容器尺寸变化（史引 40/60 分屏导致列宽/文本重排、窗口缩放），若用户仍贴在底部则重新对齐到最新消息；用户主动上翻后不强行拉回（新消息落地时按需求仍会回到底部）。

### 3.3 左侧历史记录侧边栏

- **列表锁定**：侧边栏 `height: 100%`、内部 `.scrollArea` 独立滚动，条目再多也不撑开页面；
- **悬浮「⋯」菜单**：鼠标悬浮 / 键盘聚焦条目时右侧出现「⋯」，点击展开 `置顶` / `重命名` / `删除` 菜单（fixed 定位、贴边翻转、点击外部 / Esc / 滚动自动关闭）；
- **置顶**：进入最上方独立「置顶」分组（无置顶项时不渲染空组），再次操作为「取消置顶」，取消后回到原时间序；
- **重命名**：行内输入框，Enter / ✓ 保存，Esc / ✕ 取消；重命名会锁定标题，不再被后续首问标题覆盖，且不改变列表位置；
- **删除**：该条消失，其余条目相对顺序不变（下面项自然上补；删除当前会话时聊天区回到欢迎语）；
- **新建对话**：顶部固定「+ 新建对话」入口；点击后聊天区清空回欢迎语、**立即创建**一条新会话记录（`updatedAt = now`）并出现在列表最上方；当前已是空白会话时不重复创建；
- **选中态**：仅改变背景（浅灰 `#ece9e2`）与文字色，绝不通过排序 / DOM 顺序实现「高亮」。

### 3.4 状态层排序契约（关键修复）

`frontend/lib/conversation-store.ts` 明确区分两种写入：

| 方法 | 语义 | `updatedAt` | 使用场景 |
|---|---|---|---|
| `save(id, turns, title?)` | 会话内**真的产生新消息** | 刷新为 now（最后一条消息发送时间） | 发送问题 / 收到回答 / 错误兜底轮次落地 |
| `syncTurns(id, turns, title?)` | 只同步正文（查看 / 离开） | **不变** | 加载历史会话、切换前保存当前会话 |

配套修改：

- `AgentContext` 维护「已同步签名」`transcriptSignature(turns)`：切换 / 加载会话后先登记签名，让 transcript 同步 effect 跳过 save，从根上消除「查看触发重排」；
- 只有 transcript 轮次数增长时才调用 `save`（touch），否则 `syncTurns`；
- 重命名锁定 `titleLocked`，`save` 不再用首条用户消息覆盖自定义标题；
- 分组函数 `groupConversationsByTime` 输出「置顶 / 今天 / 过去 30 天」，排序严格按 `(pinned, updatedAt desc)`，与点击行为解耦。

## 6. 已知边界与非目标

- 历史对话仍是**内存演示数据**（刷新回到演示集），重命名 / 删除 / 置顶只在本地内存生效；持久化、跨会话上下文、重命名 / 删除的落盘仍按 `// TODO v1.0.6 多轮历史对话记忆模块 - 功能待实现` 预留；
- 点击历史记录创建会话记录的行为不变：刷新后当前会话会作为「最新活跃」出现在列表顶部（这是当前会话，不是点击重排）；
- 未改后端 API 契约、未改 Agent 能力；`/api/search/events` 契约桩与运行实现差异见 V1.0.5.3 体检 findings（F-14）。
