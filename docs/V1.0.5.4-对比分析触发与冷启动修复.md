# V1.0.5.4 · 对比分析触发与冷启动修复说明

> 版本背景：V1.0.5.4 引入「二次归纳 / 史令对比分析」后，真实测试暴露了对比意图漏判、
> 提前判定 `insufficient`、新窗口冷启动异常、证据链误杀四类问题。
> 本补丁**不改变三态语义、不破坏防幻觉底座**（`markdown` 仍由服务端用工具真实返回重写、
> 模型文本不进入事实实证），只修复触发覆盖、对比兜底、校验口径与冷启动状态隔离。
>
> 相关文件：`backend/agent/{validator.py,comparison.py,orchestrator.py,prompts.py}`、
> `frontend/{contexts/AgentContext.tsx,lib/agent-client.ts}`、
> `backend/tests/{test_comparison_analysis.py,test_agent_api.py}`、
> `frontend/tests/agent-client.test.ts`、`scripts/health-check-ui.mjs`；
> 前置设计见 [`V1.0.5.4-对比分析设计.md`](V1.0.5.4-对比分析设计.md)。

## 1. 缺陷现象

| # | 现象 | 复现输入 |
| --- | --- | --- |
| B1 | 前端已检索出秦始皇 / 刘邦基础事实，最终却返回 `insufficient`「抱歉，现有的历史数据无法完整回答您的问题」，**完全没有触发二次归纳** | 刘邦统一汉朝和秦始皇统一六国的历史意义和影响一样吗 |
| B2 | 正常返回【史料实证】+【史令对比分析】（正常基线） | 商鞅变法与王安石变法的区别 |
| B3 | 新窗口 / 冷启动偶发状态丢失、异常报错（HTTP 503 `LLM_NOT_CONFIGURED`，消息体为 `messages[N].content 超过 20000 字`）、对比不触发 | 上述问题在全新窗口直接提问 |
| B4 | 对比分析提到了图谱里已有的人物 / 年份，却被校验器整段丢弃 | 分析引用「秦始皇」「公元前221年」而事实块文本只提取到部分信息 |

## 2. 根因分析

### 2.1 B1：对比意图白名单硬编码（漏判）

旧实现 `validator.detect_comparison_intent()` 只有 6 个关键词：

```
对比 / 区别 / 异同 / 有什么不同 / 比较 / 异同点
```

「…一样吗」「谁的影响更大」「相比如何」「差异」等隐式对比问法全部漏判，
二次归纳开关根本不打开；同时 `detect_question_focus()` 也把这类问题误判为 `person` / `event`，
双源覆盖硬校验按错误的问题类型执行，进一步把可回答的对比问题降级成 `insufficient`。

### 2.2 B2：`insufficient` 判定早于二次归纳（门槛过高）

旧流程是「模型最终回答 → 证据校验 → grounded 才二次归纳」，因此只要模型自己写了
`insufficient`、或证据校验降级（例如只提交了时间轴事件、没提交人物关系图证据），
就会在二次归纳**之前**直接返回资料不足。对比类问题的正确口径是：

> 只要图谱（人物关系 + 时间轴）返回了 A 和 B 的实体数据，就必须把基础事实交给模型做二次归纳；
> 除非 A 和 B 连图谱实体都没查到，否则不要轻易报 `insufficient`。

### 2.3 B3：工具结果消息超过 LLM 单条消息上限（503）

`prompts.MAX_TOOL_BATCH_RESULT_CHARS = 24000`，而 `llm_client.MAX_CHAT_MESSAGE_CHARS = 20000`：
一轮 `tool_batch` 的 2 条各 12000 字结果拼成一条 user 消息后会超过 20000 字，
`LLMClient` 抛 `LLMConfigError`，API 层映射成 **503 `LLM_NOT_CONFIGURED`**，
前端表现为「新窗口提问异常报错」。该问题与窗口无关，只是新窗口提问时更容易撞上。

### 2.4 B4：证据链校验过严（误杀合法分析）

- 人物白名单只来自**已提交 evidence 的事实块子集**：问题主体（如秦始皇 / 刘邦）明明在本轮
  图谱实体里，只要模型没把它写进 evidence，分析里提到就会被判「事实块外人物」整段丢弃；
- 年份必须**逐字精确命中**：分析写「公元前221年」而事实块文本只提取到「221年」时被误杀。

### 2.5 B5：冷启动 / 新窗口状态隔离

- `sessionStorage` 里旧版本序列化的 `answer` 可能缺少 `citations` / `uiActions` / `sources` /
  `comparisonAnalysis` 字段，恢复后直接渲染会访问 `undefined`（新窗口恢复即报错）；
- 模型注册表加载完成前 `selectedModelId` 为 `null`，请求不带 `model_id`；
  而把前端静态兜底模型 id 硬塞给后端时，若后端 `.env` 换了模型又会被判「未知模型 400」；
- `session_id` 采用「第一次 ask 时懒生成」，冷启动首问依赖该分支正常执行。

## 3. 修复内容

### 3.1 修复一：对比意图全面覆盖（防漏判）

`backend/agent/validator.py`

- `_COMPARISON_CUES` 扩展为显式（对比 / 比较 / 相比 / 相较 / 区别 / 差别 / 差异 / 异同 /
  异同点 / 相同点 / 不同点 / 有何不同 / 有什么不同 / 不一样 / 不同在哪 …）与
  `_COMPARISON_PATTERNS` 隐式句式：`一样吗|相同吗|相似吗`、`谁/哪个…更(大|重要|深远…)`、
  `不同/差异…在哪`、`有(什么|何|哪些)…不同`；
- `detect_comparison_intent()` 与 `detect_question_focus()` 共用 `_matches_comparison_cues()`：
  隐式对比问题同时被判定为 `comparison`（双源覆盖按对比类口径、分节顺序稳定）；
- 无硬编码白名单，纯确定性匹配、无额外模型调用。

### 3.2 修复二：`insufficient` 拦截门槛放开（对比兜底）

`backend/agent/orchestrator.py` + `backend/agent/comparison.py` + `backend/agent/validator.py`

新增 `AgentOrchestrator._try_comparison_rescue()`，在**任何**最终回答将要返回
`insufficient`（模型自述资料不足 / 证据校验降级 / 收尾轮失败兜底）之前接管：

1. `detect_comparison_intent(question)` 为真；
2. `comparison.find_comparison_subjects()` 在本轮图谱事实中找到 **A / B 双方实体**：
   - 人物按问题中的正名 / 别名匹配本轮 person 实体（按问题出现顺序）；
   - 事件按标题在问题中出现、或事件参与者姓名在问题中出现匹配（如「王安石变法」→「熙宁变法」）；
   - 问题明确出现 ≥2 位已知历史人物时，才允许退化为「本轮 ≥2 个详情级人物 / 事件」；
   - 匹配不足 2 个主体 → 返回 `None`，保持原 `insufficient`（A/B 图谱实体确实没查到）；
3. `validator.compose_rescue_grounded()` 用本轮真实工具返回重新合成 grounded 正文
   （只取 `fact_usable`、非 list 形态、被 citation 绑定的实体，与正常 grounded 同口径）；
4. 立即触发二次归纳并做证据链校验：
   - 通过 → `grounded` + `comparison_analysis`；
   - 模型分析失败 / 非 JSON / 校验不过 → **仍返回 grounded 事实实证**（`comparison_analysis=null`）；
5. 服务端写死 `claims` / `citations` / `certainty` / `source_coverage`，模型文本不进入 `markdown`。

主循环与收尾轮两个返回点、收尾兜底 `_fallback()` 之前都接入了该兜底。

### 3.3 修复三：新窗口 / 冷启动状态隔离

`frontend/contexts/AgentContext.tsx` + `frontend/lib/agent-client.ts` + `backend/agent/{prompts,orchestrator}.py`

- **恢复归一化**：新增 `normalizeRestoredAnswerView()`，把 `sessionStorage` 里旧版 answer
  缺失的 `citations` / `entities` / `uiActions` / `sources` / `comparisonAnalysis` 补成安全默认值，
  结构非法 / 空正文回退 `null`（回落欢迎语），不再出现新窗口恢复即空指针；
- **`model_id` 策略**：新增 `resolveRequestModelId()`——已选模型 → 直接用；注册表就绪 →
  带后端默认主模型；注册表尚未返回的极早期 → 不带 `model_id`（由后端默认主模型处理，
  避免把前端静态兜底 id 硬塞给后端造成「未知模型 400」）；
- **`session_id` 初始化**：Provider mount 时即生成（不再依赖首次 ask 懒生成），
  冷启动第一问必定带合法 `session_id`；`history` 为空时 `buildAskRequest` 正常组装空数组；
- **模型注册表读取兜底**：`fetchAgentModels` 增加 `.catch`，异常时回退静态注册表并置 `modelsReady`，
  不再把 rejected promise 变成新窗口首屏控制台报错；
- **后端消息长度兜底**：`MAX_TOOL_RESULT_CHARS` 12000→10000、`MAX_TOOL_BATCH_RESULT_CHARS`
  24000→16000、新增 `MAX_TOOL_MESSAGE_CHARS=18000` 最终裁剪；Orchestrator `_shrink_messages()`
  对非 system 消息统一裁到 19000 字，保证任何请求都 < `LLMClient` 的 20000 字单条上限。

### 3.4 修复四：二次归纳证据校验兜底（防误杀）

`backend/agent/comparison.py` + `orchestrator._request_comparison_analysis()`

- **人物**：校验放行名单 = 事实块白名单 ∪ **本轮图谱实体中出现过的人物名 / 别名**
  （`observed_graph_person_names()`，含关系两端、仅在列表中出现的人物）；
  「只要人物在图谱实体（秦始皇、刘邦）中就放行」；
- **年份**：`_year_is_verified()` 增加纪年前缀模糊匹配——分析写「公元前221年」而事实块
  只有「221年」时按绝对值放行；真正不同的年份仍然拦截；
- 空文本 / 超长 / 越狱指令清理后为空等原有规则不变（失败仍只丢弃分析、不降级）。

### 3.5 二次归纳 Prompt 补强

`backend/agent/prompts.py`：输出协议补充「问题追问历史意义 / 影响时要分别说明 A 与 B 在
事实块里能支撑的意义 / 影响并指出异同」；明确「材料有限也必须给出基于事实块的归纳，
材料不足的维度写『材料未提供 / A 与 B 的对比信息不足』，不要整段空泛或拒答」。

## 4. 触发与兜底判定矩阵

| 模型最终回答 | 对比 / 总结意图 | A/B 图谱实体 | 行为 |
| --- | --- | --- | --- |
| grounded（证据通过） | 是 | — | 正常事实实证 + 二次归纳分析（校验不过只丢分析） |
| grounded | 否 | — | 普通事实实证，不额外调用模型 |
| insufficient / 校验降级 | 是 | 双方都查到 | **对比兜底**：服务端事实正文 + 二次归纳 → grounded |
| insufficient / 校验降级 | 是 | 只查到一侧 / 都没有 | 保持 insufficient |
| insufficient | 否 | — | 保持 insufficient（固定模板） |
| refusal | — | — | 保持 refusal（兜底不接管拒答） |

不变量：`insufficient` 的固定文案 / 枚举 missing、`refusal` 的固定文案、`markdown` 由服务端用
工具真实返回生成、`comparison_analysis` 仅 grounded 可携带（Pydantic 强制）均保持不变；
`SCHEMA_VERSION` 仍为 `1.0`，契约只增可选字段。

## 7. 已知边界

- 历史对话仓库仍是 V1.0.5.2 的**内存实现**：新窗口 / 刷新后侧边栏回到演示数据、
  本标签页对话从 `sessionStorage` 恢复——这属于 V1.0.6 持久化范围，本补丁只保证
  「新窗口冷启动提问不丢状态、不报错、对比正常触发」；
- 对比兜底只在「A/B 双方图谱实体都找到」时接管：A/B 名字在数据里完全不存在时仍如实返回
  `insufficient`，不会用无关事实强行 grounded。
