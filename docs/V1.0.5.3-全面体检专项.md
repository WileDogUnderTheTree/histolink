## 1. 背景与目标

V1.0.5.2 已完成功能封版（双数据源回答、模型切换、历史对话侧边栏），并在同版追加了 `/ask` UI 呼吸感补丁。项目进入 **V1.0.5.3 全面体检专项**：在 V1.0.6 多轮对话改造之前，对代码、数据、契约、测试、性能、文档与安全做一次全量健康检查，把基线从「功能可用」提升到「可回归、可维护、可发布」。

**目标**

1. 建立**可重复执行**的体检基线：自动化门禁 + UI 无头体检 + 静态质量 + 数据告警 + 版本一致性，一次采集、可随时复跑。
2. 输出**分级 findings 清单**（P0 阻断 / P1 本版修 / P2 排期 / P3 顺手修），并给每条结论留下可复现证据。
3. 只修 **P0 / P1 与门禁稳定性**；P2 明确排期到 V1.0.6 / V1.0.7，避免体检变成无边界重构。
4. 为 V1.0.6 多轮对话提供稳定基线：门禁在 Windows（`core.autocrlf=true`）与 LF 工作区都必须可复现通过。

**非目标**

- 不新增业务功能、不改 Agent 能力与外部 API 契约；
- 不做 V1.1 级别的 UI 大改（3D、滑块交互等）；
- 不做数据大规模扩充（V1.0.5.4 数据批次另行推进）。

## 7. 阶段 2 详细计划（2026-11-26 起）

### 7.1 B 维度：可访问性 / 响应式矩阵

- 断点矩阵：1600 / 1440 / 1280 / 1080 / 900 / 820 / 720 / 390 宽度下逐页截图 + 横向溢出 / 遮挡断言（扩展 `health-check-ui.mjs` 为 `--matrix` 模式）。
- 键盘走查：Tab / Shift+Tab 顺序、`Enter` / `Space` 激活、`Esc` 关闭浮层；所有交互控件 `:focus-visible` 可见。
- 对比度：正文 / 次要文字 / 按钮文字对 WCAG AA（4.5:1）抽查；`prefers-reduced-motion` 下无动画。
- aria / 语义：`aria-expanded` / `aria-label` / `role` 完整性；屏幕阅读器（Edge + Narrator）走查侧边栏与引用折叠。

### 7.2 C 维度：后端错误矩阵与并发

- 错误矩阵：模型未配置 503、超时 504、上游 502、未知模型 / 非法请求 400、RAG 不可用降级路径；清理提示文案与 HTTP 状态码一致性。
- 并发：同一会话并发 `POST /api/agent/ask`、多浏览器标签共享 `sessionStorage` 会话的竞态；确认后端无共享可变状态。
- 日志脱敏：grep `API_KEY` / `Authorization` / 用户问题原文在日志中的落点，确认不写密钥、不写完整 prompt。

### 7.3 F 维度：生产性能基线（F-10）

- `next build` + `next start`（临时端口，测完关闭），CDP Performance 采集 `/` `/ask` `/timeline` `/graph` 的 LCP / CLS / TBT / 资源传输量。
- 产出「性能基线表」写入本文 §7 执行记录；超过阈值（如 LCP > 2.5s）登记新 finding。
