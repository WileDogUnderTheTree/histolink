# V1.0.5.4 · 图谱数据全自动清洗与合并说明

> 版本：V1.0.5.4（数据扩充：先秦早期 · 夏商西周）
> 脚本：`backend/scripts/ingest_graph_data.py`（配套 `scripts/ingest-data-helper.mjs`、`scripts/check_consistency.py`）
> 目的：把 WorkBuddy 按《史脉》规范产出的「图谱扩充」Markdown 一次性自动合并进前端数据层、人物主数据与后端快照，
> 免去每次手工改 `person-graph.ts` / `person-relations.ts` / `timeline-events.ts` 的合并风险。

---

## 1. 一键操作（后续批次同样适用）

```bash
# 1) 把 WorkBuddy 产出的图谱扩充文件放进 docs/（文件名建议：史脉_V1.0.5.4_图谱扩充_<朝代>.md）
#    当前脚本默认扫描：docs/史脉_V1.0.5.4_*.md（含本次的「史脉_V1.0.5.4_先秦早期扩充_夏商西周.md」）

# 2) 全自动：解析 → 合并 → 重写生成物 → 重建 persons / sources / snapshot → 全量数据校验 → RAG 一致性检查
python backend/scripts/ingest_graph_data.py

# 3) 刷新 http://127.0.0.1:3000/graph 即可看到新分期 Tab / 新人物 / 新关系
```

脚本可反复运行：所有输出确定性排序、无时间戳，重复执行字节级一致。
常用参数：

| 参数 | 用途 |
| --- | --- |
| `--dry-run` | 只解析并打印「新增 / 复用 / 跳过」汇总，不写盘、不跑流水线（先看合并计划） |
| `--check` | CI 用：校验生成物是否与 docs 一致（过期即非 0 退出，不写盘） |
| `--skip-node` | 只写生成物，不跑 Node 流水线（调试解析逻辑时用） |
| `--skip-consistency` | 跳过 `scripts/check_consistency.py` |
| `--pattern "史脉_V1.0.5.4_*.md"` | 覆盖配置里的扫描 glob |

## 2. 输入数据规范（WorkBuddy 交付格式）

每份文档需包含两张 Markdown 表（列名不必逐字一致，脚本按关键词识别）：

**表一：核心事件**

| 朝代 | 年份(公元) | 事件名称 | 事件简述 | 参与人物 | 重要度(1-3) |
| --- | --- | --- | --- | --- | --- |

- 年份支持 `约前2100` / `前1046` / `前1046后` / `约前1400-前1300`（跨年取起始年）；
- 参与人物用中英文逗号 / 顿号分隔；
- 重要度 `3` = 时间轴简阅（顶级事件）必须展示，`2` = 细览，`1` = 补充节点（当前无 1 级数据）。

**表二：人物关系**

| 所属朝代 | 人物A | 人物B | 关系 | 共同参与事件 | 关系简述 |
| --- | --- | --- | --- | --- | --- |

「共同参与事件」是关系锚点：脚本会解析成事件 id 并校验两人确实共同参与；若来源表只列了单方
（如父子 / 夫妻等天然关系），脚本按 **关系驱动参与人补全** 把双方补进锚点事件，保证关系在图中成为一条边
（与 V0.6.3 既有先秦关系「周公旦 × 周康王 锚定成康之治」的既有口径一致）。

## 3. 脚本做了什么

```
扫描 docs/史脉_V1.0.5.4_*.md
   ↓ Node 辅助脚本读取基准数据层索引（去掉上一次生成物后的 705 事件 / 639 关系 / 18 期）
   ↓ 解析表一 / 表二
   ↓ 人物归一化（canonical_person_names：大禹→禹、桀→夏桀、帝辛→商纣王、周公（周定公）→周定公、召公→召穆公 …）
   ↓ 事件去重合并（标题同题 / event_title_map 登记的同一史实 → 复用既有 event_id）
       ├─ 新参与人 → 追加 participants（含关系锚点补全）
       ├─ 重要度「就高」覆盖（如 三监之乱 提升为 3 → 进入时间轴简阅）
       └─ 标题高度相近但未登记的事件 → 打印警告，提示人工补 event_title_map
   ↓ 新事件：按「朝代拼音 + 标题拼音 + 两位序号」生成稳定 event_id（如 xia-tushanzhihui-02）
   ↓ 人物关系：复用 / 新增 / 关系补丁三态合并，pairKey 去重，绝不重复收录手写关系
   ↓ 新增人物：按「朝代拼音 + 人名拼音 + 两位序号」固定可读 person_id（如 p-xizhou-zhoudinggong-01）
   ↓ 新图谱分期：docs 里出现、但既有 person-graph 尚未覆盖的朝代 → 自动生成分期（夏 / 商 / 西周）
        · 事件池自动带「上一朝代」作前史（商含夏、西周含商），与南宋含金同一口径
        · 默认中心人物 / 名人堂按事件度数自动计算，可在 config 固定
   ↓ 别名映射（异名归一 + extra_person_aliases）
   ↓ 写出生成物：frontend/data/ingested-graph-data.generated.ts + backend/data/ingest/person-id-pins.json + docs/图谱数据入库报告.md
   ↓ 运行既有流水线：build-persons → extract-sources → export-snapshot → validate-data
   ↓ 运行 scripts/check_consistency.py：快照引用完整性 / 孤儿节点 / RAG 名词覆盖
```

### 2.1 生成物与接线（只写生成物，不改手写数据）

| 生成物 | 内容 | 接线位置 |
| --- | --- | --- |
| `frontend/data/ingested-graph-data.generated.ts` | 新事件 / 参与者增补 / 重要度覆盖 / 别名 / person_id 固定 / 新增关系与补丁 / 新分期 / 名人堂 | `timeline-events.ts`、`timeline-participants.ts`、`person-graph.ts`、`person-relations.ts`、`persons` 生成器 |
| `backend/data/ingest/person-id-pins.json` | 新增人物的可读 person_id 固定表（跨批次稳定，**不要手改**；人工固定写 config） | `build-persons.mjs` 读取 |
| `frontend/data/locks/data-counts.lock.json` | 全量冻结计数（事件 / 人物 / 关系 / 分期 / 引用条数） | `validate-data.mjs` + pytest 基线，数据扩充后自动刷新 |
| `docs/图谱数据入库报告.md` | 本次解析 / 合并 / 跳过 / 新增的完整留档 | 人工复核用 |

> 手写文件（`timeline-participants.ts`、`person-relations.ts`、`person-graph.ts` 的基础数据）保持只读；
> 所有「扩充数据」都进生成物，避免脚本正则改大文件带来的合并风险。

### 2.2 同名异人（硬规则）

- `周公旦`（摄政）固定 ID `p-xizhou-zhougongdan-01`；
- `周定公`（共和行政）固定 ID `p-xizhou-zhoudinggong-01`；
- 两者完全不同的事件集合，`config.person_id_pins` 显式固定；脚本、`build-persons`、`validate-data` 三层校验
  「固定 ID 唯一 + 不与自动 hash ID 冲突」，**绝不按姓名相似合并**；
- 别名表里 `周公（周定公）` 只指向 `周定公`，不会解析到摄政周公旦。

### 2.3 别名归一（硬规则）

| 别名 | 主键 | 说明 |
| --- | --- | --- |
| 桀 | 夏桀 | 新数据统一用「夏桀」，旧称「桀」保留为别名；图谱搜索「桀」命中夏桀节点 |
| 大禹 | 禹 | 既有数据用「禹」，扩充表用「大禹」，归一到同一人物 |
| 商纣王 | 商纣王 | 帝辛 / 纣王 → 商纣王 |
| 姜子牙 | 姜子牙 | 吕尚 / 姜尚 / 太公望 → 姜子牙 |
| 周定公 | 周定公 | 周公（周定公）→ 周定公（不指向周公旦） |
| 召穆公 | 召穆公 | 召公 → 召穆公（周厉王时期召穆公虎） |

## 4. 配置文件

`backend/data/ingest/config.json`（唯一手改入口）：

| 字段 | 作用 |
| --- | --- |
| `doc_globs` | 扫描哪些 docs 文件（默认 `史脉_V1.0.5.4_*.md`） |
| `doc_exclude_patterns` | 排除非数据文件（如 `史脉_V1.0.5.4-说明.md`） |
| `canonical_person_names` | 异名 → 主键（只写需要归一的） |
| `extra_person_aliases` | 额外别名映射（如 `桀 → 夏桀`） |
| `person_id_pins` | 人工固定的 person_id（**周公旦 / 周定公 / 夏桀 在这里固定**） |
| `dynasty_ids` | 朝代 → 拼音前缀（event_id / person_id 用） |
| `event_title_map` | 文档标题 → 既有 event_id（同史实异名去重，如 `甘之战 → xia-06`） |
| `event_source_map` | 新事件的史源括注（`《史记·夏本纪》` 等；未配置时按朝代兜底） |
| `event_participant_additions` | 来源表只列主角、但史料明确共同参与的人物（如 `周穆王西征 + 祭公谋父`，避免孤立节点） |
| `era_defaults` | 新分期的 id / 默认中心人物 |
| `era_extra_dynasties` | 新分期事件池包含的前史朝代（商含夏、西周含商） |
| `era_scope_map` | 新分期 → 简阅断代（夏商西周 → 先秦） |
| `key_figure_size` | 新分期名人堂人数（默认 8） |

> 后续批次若出现「同一史实的另一种写法」导致事件重复或分不清，先在 `event_title_map` 登记即可；
> 脚本对未登记的近似标题会打印警告，不会静默猜测。

## 5. 验收与回归

```bash
# 数据层
python backend/scripts/ingest_graph_data.py --check     # 生成物是否最新（幂等）
node scripts/build-persons.mjs --check
node scripts/extract-sources.mjs --check
node scripts/export-snapshot.mjs --check
node scripts/validate-data.mjs                          # 事件 / 图谱分期隔离 / 关系 / 别名 / 人物主数据 / 快照
python scripts/check_consistency.py --strict            # 快照完整性 + 孤儿节点 + RAG 名词覆盖

# 应用层
cd frontend && pnpm exec vitest run                     # 含 ingested-graph.test.ts（本批数据 14 条回归）
cd backend && .\.venv\Scripts\python.exe -m pytest -q   # 全量后端
pwsh scripts/verify.ps1                                 # 12 步门禁（含 next build / evals / 契约）
```

`scripts/check_consistency.py` 的核心输出：

- 快照内部引用完整性（事件 ↔ 人物 ↔ 关系 ↔ 图谱节点）；
- 孤儿节点：图谱孤立人物、仅时间轴人物、未进入图谱的事件（warning）；
- **RAG 名词覆盖**：扫描 `docs/史脉_RAG语料库_*.md`，检查「大禹 / 商汤 / 伊尹 / 夏桀 / 周公旦 / 周定公 …」
  等核心实体是否都能在 persons（含别名）与 events 中命中；缺失时打印警告清单。

   在 `person-graph.ts` 的 `INGESTED_ERAS` 构建处调整 `spec.dynasties` 即可。

   「新增」变「复用」，其 id 会消失并重新生成，属预期变更（会同步刷新锁文件与快照）。
4. **版本号**：本批只做数据与生成物，`APP_VERSION` 仍为 `1.0.5.2`；如需发版，按 README §发布流程统一更新。
